# Pattern catalog

Each row: a modern-operations pattern, what it means, and **where it is live in
this fleet** — with a link to the evidence. Rows are harvested from the fleet
repos' `🧭 What this repo demonstrates` sections; nothing lands here without a
citation.

| Pattern | What it means | Live in the fleet |
|---|---|---|
| **Plan-on-PR / apply-on-merge** | The proposed change is reviewed as a machine-computed diff; the merge itself triggers the apply. The merged PR *is* the change record. | [solidago `terraform.yml`](https://github.com/lentago/solidago/blob/main/.github/workflows/terraform.yml) posts the plan as a PR comment and applies on main; [drosera](https://github.com/lentago/drosera) applies dashboards on every merge; [kalmia](https://github.com/lentago/kalmia) applies the Proxmox guest layer via a LAN runner. |
| **Keyless cloud auth (OIDC)** | CI proves its identity to the cloud with short-lived federated tokens — no stored access keys to leak or rotate. | [solidago's IAM trust split](https://github.com/lentago/solidago/blob/main/docs/WORKLOAD_RELATIONSHIP.md): an infra role and a workload role, each scoped to specific repo+environment subject claims; the site repos deploy through the workload role. |
| **Blast-radius containment by trust policy** | Separate credentials per concern, so compromising one pipeline can't reach another's permissions. | Same trust split: the workload role can push images and deploy services but cannot touch infrastructure; the infra role never runs in workload repos. |
| **Required checks that cannot deadlock** | A required check whose workflow is path-filtered gets stuck "Expected" forever on non-matching PRs. Fleet rule: only require contexts that report on *every* PR — terraform repos use an always-on `gate` fan-in job. | The rule and its origin story live in [`fleet-ops/required-checks.json`](https://github.com/lentago/.github/blob/main/fleet-ops/required-checks.json) (see lentago/.github#27); [music-curator's `integrity.yml`](https://github.com/lentago/music-curator/blob/main/.github/workflows/integrity.yml) runs unconditionally for the same reason. |
| **Reusable CI, consumed not copied** | CI logic lives once in a `workflow_call` library; repos are thin wrappers, so a fix propagates fleet-wide without copy-paste drift. | [shared-workflows](https://github.com/lentago/shared-workflows) provides docs-check, the `@claude` responder, and PR review; every repo's `.github/workflows/docs-check.yml` is a 3-line wrapper. |
| **Settings-as-code** | Repo existence, rulesets, required checks, topics, and labels are config in git — drift shows up as a diff, and one edit moves the whole fleet. | [.github `fleet-ops/*.json` + `terraform/`](https://github.com/lentago/.github/tree/main/fleet-ops): `repos.json` is the source of truth for which repos exist; adding an entry creates a repo scaffolded from the template. |
| **Live-state vs. code discipline** | On an enforced surface, whatever is on `main` IS production — a live-only edit survives exactly until the next apply. | The lesson was learned live: dashboard work pushed via the Grafana API but never committed was silently reverted by unrelated merges, then restored from version history in [drosera#119](https://github.com/lentago/drosera/pull/119). The rule now lives in drosera's CLAUDE.md. |
| **GitOps pull loops with validate-then-apply** | The target system pulls desired state on a timer, validates, applies the lightest reload, and rolls back on failure — no push access into production needed. | [homeassistant-config `gitops-sync.sh`](https://github.com/lentago/homeassistant-config/blob/main/scripts/gitops-sync.sh) (5-min poll, Supervisor validate, auto-rollback + mobile alert); claytonia's `bullpen-gitops` timer redeploys worker tooling the same way. |
| **Agent fleet behind a human merge gate** | Autonomous agents do directed work at scale, but nothing they produce reaches `main` without a person reading the diff. | [claytonia](https://github.com/lentago/claytonia): workers branch and open PRs via a GitHub App that *cannot* merge, and the runner actively disarms auto-merge on bot PRs. |
| **Audit trail for agent configuration** | The standing instructions that shape agent behavior are production config — snapshot them append-only so tampering becomes a reviewable diff, not silent state. | Documented publicly in [claytonia → docs/context-ledger.md](https://github.com/lentago/claytonia/blob/main/docs/context-ledger.md) (the ledger repo itself is private by design, and deliberately outside the org). |
| **The paved road** | New repos start compliant — template files plus enforced settings — instead of drifting toward compliance later. | [repo-template](https://github.com/lentago/repo-template) (files) + fleet settings-as-code (settings); this very repo was born on it. |
| **AI-queryable docs by default** | Documentation is structured so an AI can answer from it — then every repo becomes ask-able instead of spelunk-able. | Every public repo is indexed on [DeepWiki](https://deepwiki.com/lentago) and links it as the repo homepage; READMEs carry starter questions. |
| **Operate in the open** | The fleet reports on itself — activity, code census, and post-mortems are published artifacts, regenerated by CI. | [Weekly fleet report](https://github.com/lentago/.github/blob/main/fleet-reports/fleet-report.md) + [incident register](https://github.com/lentago/.github/blob/main/fleet-reports/incidents.md) (published verbatim by deliberate policy). |
| **Cost guardrails as code** | Budgets and alert thresholds are declared, versioned resources — not console toggles someone once set. | [solidago `modules/budgets`](https://github.com/lentago/solidago/tree/main/modules/budgets): AWS Budgets with SNS alerts at 50/80/100%. |
| **Fail-loud secret hygiene** | Pipelines that touch config files scan for secrets at collection time and abort loudly — a hit is a finding, never a warning. | The context-ledger collector quarantines on any secret-pattern match ([claytonia docs](https://github.com/lentago/claytonia/blob/main/docs/context-ledger.md)); [homeassistant-config](https://github.com/lentago/homeassistant-config) runs full CI validation against `secrets.fake.yaml` so real values never enter CI. |
| **Tiered automation trust** | Automation isn't all-or-nothing: auto-merge the provably-safe class, hold everything else for a human with an explanatory comment. | [music-curator `follow-fold.yml`](https://github.com/lentago/music-curator/blob/main/.github/workflows/follow-fold.yml): safe reservoir seeds auto-merge; discards and unfollows are held with a bot explanation. |

**Missing a row?** If a fleet README demonstrates something this catalog
doesn't cover yet, add it — with the evidence link — via PR.
